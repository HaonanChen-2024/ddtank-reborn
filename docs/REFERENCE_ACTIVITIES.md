# 本地参考活动

本轮范围是参考截图中的17种活动。当前实现为可运行的网页过渡版本；用户后续确认优先移植参考原窗口/动画/流程，因此不能把此阶段算作完整移植。充值来源改为本地任务积分；不接真实付款，不修改等级门槛、武器属性或现有角色货币。仅图标、单元测试不代表游戏中验收完成。

## 已实现的代码

- `apps/api/src/activities`：扫雷、配对、随机货架、寻宝临时包、转盘追加、骰子探险、三列转轴、狂欢骰盘、雪地找雪人，以及任务/分档礼物。数值和部分规则是明确展示的本地版本，不宣称复刻未知的参考服服务端。
- 魔法衣橱展示公开 `MagicClothList.xml` 的52套部件目录，区分真实持有、已安装及未安装。目录不代表资源已全部导入，不制造新装备。
- 签到继续由原 `CalendarManager` 窗口和游戏服务处理；原材料兑换也继续存在。活动中心的材料商店使用独立活动积分，明确区别原配方。
- `ActivityCenter` 位于原游戏 Play 页内。17个图标来自参考静态资源的命名位图，统一用中文文本替换展示标题；原充值文字不作为本地解锁条件。激活礼包位于次级“礼包服务”。
- `workshop-activity-entry.mjs` 只改变大厅点击与回调注册两个原 ABC owner。新页面桥返回严格 true 才拦截原主菜单；旧宿主保留原行为。激活和签到回调仅打开原窗口，不调用领取方法。

## 积分、持久化与邮件

新增迁移 `0006_reference_activities`，只添加 `app.ActivityWallet`、`ActivityStates`、`ActivityActions`。游戏货币、在线背包和装备基础属性不由活动 API 直接写入。

每次写入先验证登录账户及角色归属，再锁该角色的钱包行。积分变化、私有棋盘、请求回执、绑定物品附件和邮件在同一事务提交。相同 requestId+动作重试只返回当前视图与原回执；不同动作复用编号返回409。提交后的117通知失败不重复发奖。回执只存消息和邮件数，避免每次操作重复保存17个完整界面。

GET 不创建状态，不返回隐藏的雷区、牌序或雪人位置。奖励仅允许已核普通材料模板，按 MaxCount 分栈、每封最多5附件。任务积分来自服务端棋盘/寻宝进度和原签到已提交记录，客户端不能自报完成。累计任务积分不计入抽奖返还或回收所得。

前端超时、网络错误、401/403/408/429/5xx均保留原请求编号，重新登录后可明确重试。刷新页面不会自动重发。不确定操作未处理前，禁止开始新的消费操作。

每日界限沿现役UTC日，即北京时间08:00。棋盘和临时包跨日保留，日限额重置。每日500次仅限制新玩法/消费；衣橱浏览、模式切换以及已产生奖励的结算不计次，旧存档到达上限也可领取，原有资格/一次性校验保持。数值、奖池和阈值见 `config.ts` 及各活动展示规则；当前只发普通石材，保持官方模板基础属性。

## 验证边界与剩余差异

### 原窗口移植检查点（2026-10-15）

原衣橱由 `scripts/workshop-native-wardrobe.mjs` 构建6个运行文件和唯一桥接ABC；`workshop-literals.mjs --native-wardrobe=<manifest>` 可组合安装、验证及回滚。桥只在原客户端注册回调，打开前和异步完成时核对真实角色及大厅状态；取消加载不会晚到弹窗。Bootstrap保留92个原业务/依赖类、3套布局和原52套目录，仅展示本地模板齐备的31套，不生成装备或修改属性。8张精确缺失预览PNG已另行安装。

正式 `/play` 入口打开、角色不一致拒绝和立即取消已验证。较早候选11页/31套翻页通过；正式版本连续翻页在7页后出现Ruffle `stack.rs:92` GC断言，稳定性未通过。商城类型异常也出现在同份日志中，但两个相关ABC与此前版本逐字节相同，尚未建立因果。活动中心默认保留目录，原窗口明确标为试用；失败日志、截图、安装账本与恢复依赖保留。构建/HTTP完整性通过不等于运行稳定。

`pair-native` 是原32格翻牌窗口的独立本地规则：持久化已翻牌面、四种普通材料、日免费券/积分券和重置限制。GET及重放不返回动画；只有首次成功POST携带对应requestId的 `nativePairAction.effects`，原始牌序不公开。旧网页12格配对保持。70项纯逻辑、事务整合及旧活动回归通过，包含同UUID与同格竞态；原生PostgreSQL多连接和原翻牌UI尚未验收，不能据此称为原玩法完整移植。

`scripts/workshop-native-pair.mjs` 另提供未安装的原窗口候选：26个Pair类保留卡片动画，99个业务方法转入本地适配器；原支付/网络调用的静态检查通过。共享82类单独输出，必须先由唯一共享加载器协调衣橱与翻牌，不能直接重复导入。候选已编译并核对现役静态类依赖；网页回调、同UUID重试联动、两种加载顺序及原窗口运行/视觉仍待接入和验收。详见 `scripts/native-pair/README.md`。

隔离测试覆盖棋盘隐藏信息、合法动作、批量失败回滚、取回/回收互斥、跨日、积分任务、一次性礼包、并发UUID重试、真实邮件附件，以及应用重建后的恢复。真实引擎整合测试没有替换数据库或发奖逻辑；只控制随机源，签到记录使用原行为已提交的测试事实。

参考客户端的 magicWardrobe 实际是套装目录与持有部件预览，没有合成/激活发奖协议。52套目录不代表资源齐全；本地图片经过现有资源索引及文件存在检查，缺失图不伪造；Web开发服务将 `/resource` 转发到同一API。签到桥不为另一角色打开当前Flash角色窗口。

17项本地版本已经部署并从原Play页面逐项操作；正常角色完成四个任务获得200积分，13封活动邮件到账并从原邮箱领取附件。正常重启、重登保持积分/棋盘/已领状态；已查看原窗口入口和720像素宽页面。最新81项活动测试及API/Web类型检查通过；另外88项原签到/事件/API回归此前通过。累计签到原窗口完整领取、原生PostgreSQL多连接竞态未在本轮重新验收。

参考服的多人排名/全服奖池、拼团及原雪地战斗房间尚未实现；当前相应活动采用明确展示的本地可玩规则，不称为参考服务端完整复刻。已正常取得魔法衣橱、欧皇秘宝和弹弹扫雷原UI/SWF，后续先核客户端类与协议依赖，再用原窗口接入本地业务。详情以项目根目录《参考服活动完成清单.md》为准。原活动移植完成后停止，不自动恢复服饰采集等旧长期任务。
