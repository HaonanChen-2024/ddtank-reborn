Experimental and offline only. Moonlight contributes four runtime resources, 24 original Moonlight business/Morn owners including the original rank UI, the actual original `activity.ActivityNormalEvent` owner, and a minimal BitmapData glue ABC for the original claimed-reward icon (26 library ABCs total). No complete reference core or separate shared Morn library is imported. The current combined builder contains 89 assets for 16 activity modules; older package formats remain installer compatible.

The original art SWF and UI are copied byte for byte. Their SHA-256 values are `fbd265fa158117afee2f3ca0386dd1234e33fb5a56403a80cd379a565542b370` (565506 B) and `81a332f63b734f942e9fbc8ac297be9150c3d95456d6ec572202b6831ff5b39e` (4622 B). It does not wait for the looping standB animation to finish. The original skip option completes directly.

Its original constructor only extends BitmapData with width/height defaults. No other uigeneral classes or assets are imported. The main art, UI, public reference catalog and uigeneral acquisition receipts are stored under `runtime/reference-activities-completion-20261014/native-moonlight-analysis-20261015/`. The reference catalog has 96 entries and is evidence only: it is not loaded as the local reward pool or used for its private-server equipment, price, Probability or ConvertNum fields.

No selected original owner refers to that node. One queued read or explicit refresh uses GET; empty, pending or older receipt snapshots never schedule an automatic read loop. The original reward and character-preview tabs stay hidden; the left area explains the local scope, and long names use a full-name tip. Each action includes the current full date/state bagToken. The original bag shows API-projected template aggregation, preserving every original checkbox, 1..remaining quantity input, left/right, MAX and list scroll operation. Ten packages is a local per-request limit, not a recovered private-server rule. Missing count remains one package; the legacy web exchange remains one package. A single UUID commits the complete debit and all bound material mail atomically; insufficient funds, mail or receipt failure commit nothing, and replay never sends a second award. The preview labels say local material and refer to the local rule description for the guarantee.

Opening sends GET only. GET and UUID replay synchronize static state; only a fresh matching POST effect starts the original draw movie. The full movie/result transition stays locked. All help/result/bag/exchange/confirmation windows are owned by the module. Closing removes them, stops the original preview timer and movie, and preserves any unconfirmed request in the page ledger. A late draw reply cannot open a closed window or play another movie. Role, generation, sequence, revision and UUID follow the existing shared bridge contract.
