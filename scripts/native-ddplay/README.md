# Original DDPlay candidate

Offline and experimental. The combined builder emits version 1 variant `wardrobe-pair-mines-ddplay-gypsy`: 32 assets, with four for DDPlay. The previous 28-asset `wardrobe-pair-mines-ddplay` candidate remains installer compatible. The module includes the original DDPlay art SWF, a 56-definition local style closure, a Bootstrap, and an adapted library containing five DDPlay ABCs, the unchanged Back easing ABC missing from the old host, and one bitmap glue ABC. The original paid QuickBuy ABC and its styles are excluded.

Original `startLottery`, `reSetBogu` and all three `_sixBogu*Com` loops remain byte identical. The original `__lotteryCom` keeps its complete visual body and appends one acknowledgement-independent animation completion hook. Only a fresh confirmed API spin invokes the original animation; the full chain remains locked until the final reel stops. GET and replay apply static final reel positions. Timer-based continuous spins, old 74/75/76/77 packets, original purchases, chat broadcasts and global InviteManager changes are removed from executable paths or routed to a local adapter.

The common owner exposes `workshopOpenDDPlay(characterId, generation)`, `workshopStatusDDPlay()` and `workshopCloseDDPlay()`. Before open, the page attaches `workshopDDPlayRead/Request/Report`. Bootstrap callbacks are `workshopDDPlayAcceptSnapshot/RejectRequest/OpenNative/CloseNative/StatusNative`. All requests and responses use the real Self.ID in `main`, the same shared LoaderContext, generation, sequence, monotonically increasing revision and page-created action UUID. Closing kills the three original reel tweens and stops the old timer. It retains an unconfirmed action UUID in the page ledger, and a late response cannot reopen the window or replay the animation.

The API owns `nativeDDPlay` and `nativeDDPlayAction`. An explicit confirmation precedes every `{type:"spin"}` and `{type:"exchange",count:1..10}`. Both use only local activity points. Spin costs 10 points and shares the existing local DDPlay save and odds; each exchange costs 10 points and mails one bound permanent normal material 11019. The original single ratio and NumberSelecter are retained. No extra reward tiers or paid coin store are invented. Original artwork contains old 10000-point/currency labels; local text fields cover those exact regions, and the local rules and unknown original probabilities are stated in the window. Their final alignment still requires visual acceptance.

Anonymous resource downloads use only exact LoadName paths from the saved public version index. `extract-resources.mjs --check` reproduces the 56 definitions and dependency report. The original DDPlay background is not edited. The standalone exchange background bitmap payload and JPEG tables are copied unchanged from `ddtcorescalebitmap_v3_6_1_u2.swf`; no whole shared art module is imported. The missing original `SimpleFrameBackgoundOneIII` parent is replaced only inside the DDPlay style copy by the old host's standard `SimpleFrameBackgoundOne`.

`audit-candidate.mjs` checks all 31 business dispatches, original reel method bytes, the final completion hook, branch boundaries, background bitmap payload, the private singleton class identity, exact host declaration dependencies and absence of old payment/socket calls. These are compiled structural checks. Original rendering, reel/light/firework effects, close during load/read/spin, same-page module order, role drift, UUID retry and exchange-to-mail from the real original UI are not runtime accepted. Builders never deploy, open a browser, start services or write player data.
