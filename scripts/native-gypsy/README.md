# Original Gypsy Shop candidate

Offline and experimental. The combined builder emits version 1 variant `wardrobe-pair-mines-ddplay-gypsy-moonlight-treasure-purr`: 45 fixed resources, 24 callback-only common entries and 35 Bootstrap callbacks across Pair, Mines, DDPlay, Gypsy, Moonlight, Treasure and Purr. The same sole 82-ABC shared Loader serves all eight modules. Earlier 6/18/24/28/32/36/41-asset packages remain installer compatible. Four resources belong to Gypsy: Bootstrap, adapted library, original `gypsyshop_v3_6_1_u1.swf` and a local 38-definition style closure.

All 19 original `gypsyShop` ABCs were selectively decompiled for analysis. Only the eight actual window owners are imported: Event, view-model interface, item data, shop model, shop manager, product cell, help frame and main frame. The old paid confirmation managers, PurchaseModel, Controller and UILoader are excluded. The main frame's initialization, 2×4 product positions, item-list/buy-result updates, product-cell rendering/disposal and help artwork remain original. The original visible buying flow ultimately uses the host's ordinary SimpleAlert; the local adapter retains that frame for explicit confirmation and cancellation. The original UI has no quantity selector: `num` is the server's quoted package quantity.

The original `asset.core.icon.coolShining` is absent from the old host and is copied from the already-saved, pinned reference `coreii_v3_6_1_u2.swf`. FFDec 26.3.0 `getNeededCharactersDeep` and an independent shape-fill review confirmed the exact 85-tag closure: character IDs 145..229, 41 shapes, 40 bitmaps, four sprites, 108870 original tag bytes and the 40-frame root timeline. Every tag payload, ID, alpha image and timeline stays byte identical; there are no JPEG-table dependencies. A single constructor-only dynamic MovieClip glue ABC registers only this symbol. The adapted library therefore contains eight business ABCs plus one glue ABC; no whole core art ABC is imported. The separate Gypsy art SWF retains its original one ABC and 14 symbols.

The top row is explicitly labelled ordinary-material preview, using four local templates and the original BagCell/glow layout. It is constructed once per new main frame; GET, replay and purchase updates do not append glows. Close stops and disposes each old glow before disposing the frame. Original private-server rare templates, probabilities, inflated prices and payment rules are not represented as known or official.

The common entries are `workshopOpenGypsy(characterId,generation)`, `workshopStatusGypsy()` and `workshopCloseGypsy()`. The page attaches `workshopGypsyRead/Request/Report` before open. Module callbacks are `workshopGypsyAcceptSnapshot/RejectRequest/OpenNative/CloseNative/StatusNative`. The Bootstrap checks real Self.ID in main, the actual shared LoaderContext/class identities, generation, sequence, monotonic revision and the page-owned action UUID. Closing retains an unconfirmed UUID; late actions cannot reopen the frame or submit another purchase.

The API owns `nativeGypsy` and `nativeGypsyAction`. Refresh is exactly `{type:"refresh",choice:"free"|"points"}`; the first refresh each day costs zero local activity points and later refreshes cost five. Buying is exactly `{type:"buy",index:0..7,choice:shelfKey}`, with the `shelfDay:refreshes` token preventing an old index from buying a different refreshed offer. Each quoted package is available once and enters bound permanent mail. Old three-offer saves display three goods and five empty positions until an explicitly confirmed eight-offer refresh. A saved shelf date may differ from the current date. Reading and replay never generate a shelf, refresh, purchase or charge.

The copied styles replace the missing old-host `core.roundClosebt` with its existing `core.closebt`, exclude three unreachable paid confirmation definitions, add the original HelpFrame's explicit old-host frame attributes and use Microsoft YaHei for module text. Local text covers baked currency/refresh/rareness wording; the original images remain intact. These positions require visual acceptance.

`extract-resources.mjs --out=NEW_RUNTIME_DIRECTORY` reproduces the style closure from pinned resources without network. `workshop-native-gypsy.mjs` compiles a fresh independent candidate. `audit-candidate.mjs` verifies 36 business dispatches, unchanged original window/cell/help methods, private helper identities, the complete original glow closure, host dependencies and absent old payment/socket calls. The parse-only Java dependency probe and selective decompilations remain in `runtime/reference-activities-completion-20261014/native-gypsy-analysis-20261015` as evidence.

Compilation and static audits are complete; deployment and visual/runtime acceptance are not. AVM2/Ruffle typed Vector construction, frame/confirmation/help alignment, fonts, close/reopen and late-response handling, role drift, UUID retry and the actual refresh/buy/mail cycle still need the real client. Builders do not start services, open browsers, modify the original resources or write player data.
