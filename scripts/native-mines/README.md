# Original 70-cell Mines candidate

Experimental and offline only. The combined builder is `scripts/native-shared/build-activities.mjs`; it emits `workshop-native-activities`, version 1, variant `wardrobe-pair-mines`, with 24 assets. Six belong to Mines: Bootstrap, 20-ABC original library, original art SWF/UI, the 36-definition local style closure, and the original 17-action player PNG. No shared Morn library is copied or loaded by this module.

The original 21-owner module is selectively adapted. Only its global `BoguAdventureStateView` is omitted: the original GameView, 70-cell Map, Player, ChangeView and all four Morn layouts live inside an owned Sprite container. Original movement/explosion/shine methods remain unchanged; two loader-completion guards prevent disposed actors/containers from being touched. Original 140 socket subscriptions, outgoing gameplay calls, payment checks, global keyboard/cursor hooks and rank requests are removed from executable paths. Unknown old callbacks throw rather than silently doing nothing.

The sole shared owner exposes `workshopOpenMines(characterId, generation)`, `workshopStatusMines()` and `workshopCloseMines()`. It preserves the wardrobe ABI and imports the 82 shared ABCs only once. The page must attach `workshopMinesRead/Request/Report` first. Bootstrap registers `workshopMinesAcceptSnapshot/RejectRequest/OpenNative/CloseNative/StatusNative`. Every response checks current real Self.ID, `main`, generation, sequence and action UUID. AS never creates a UUID or performs HTTP/game socket requests.

Opening only reads. Explicit start creates the independent `mines-native` game; 0..69 indices map directly onto the original map. Only public `nativeMines` fields feed the model; unknown cells have no mine/count data. Fresh acknowledged walk effects animate the existing path, then reveal the destination at original STOP. Replayed/GET snapshots refresh state without effects. CellInfo references are preserved while the actor moves. Probe uses the original shine animation with input locked until its original completion event. Three manual `claim` actions use numeric tiers 1..3 and normal API mail transactions. The page owns atomic points, UUID retry and replay semantics.

Local rules are stated explicitly: 10 mines, 3 lives, first open safe, 10/30/60 safe-cell tiers, one revive per round, one free reset and three rounds per day. Probe/revive/paid reset require the displayed local point cost; no real payment, automatic exchange, automatic reward claim or rank data is simulated. The original rank tab is disabled; the reward tab displays actual local material tiers.

`workshop-native-mines.mjs` pins compiler/playerglobal and all original inputs. `native-mines/audit-candidate.mjs` checks 20 owners, adapted dispatch bodies, untouched original method bytes, valid branch destinations, both disposal guards, forbidden calls and required host classes. These are structural checks, not AVM2/Ruffle runtime acceptance. Tool acquisition and limited 21-class FFDec export receipts remain under `runtime/reference-activities-completion-20261014/native-mines-analysis-20261015`.

Pending runtime acceptance: all three first-open orders and concurrent first open; original movement, mine explosion, probe completion and 4-panel layout; cached PNG reopen/actor completion order; close during asset GET/read/action/animation with no late reopen; fresh role mismatch; all manual reward tiers and replay from original UI.
