# Shared original activity candidate

Experimental, build only. `build-activities.mjs` emits one `workshop-native-activities` version 1 manifest for the existing installer; it does not deploy, start services, open the game, or touch player data.

The current builder adds variant `wardrobe-pair-mines-ddplay-gypsy-moonlight`: 36 assets, 18 callback-only common entries and 5 Bootstrap callbacks each for Pair, Mines, DDPlay, Gypsy and Moonlight, with disjoint names. Mines retains 20 activity ABCs and six resources. DDPlay adds five business ABCs, the original Back easing class and a bitmap glue ABC in four resources. Gypsy adds eight business ABCs, one MovieClip glue ABC, the original art and 38 styles in four resources. Its original 40-frame preview glow retains all 85 shape/bitmap/sprite tags byte for byte. All six modules queue behind the same shared import. Moonlight adds 23 original module owners, the actual ActivityNormalEvent owner and a bitmap glue ABC in four resources; all three original 128-frame movie timelines and the original art/UI bytes are retained. The earlier 18-, 24-, 28- and 32-asset candidates remain preserved; the builder and ABI descriptions below describe the current 36-asset variant. See `../native-mines/README.md`, `../native-ddplay/README.md`, `../native-gypsy/README.md` and `../native-moonlight/README.md`.

The first candidate is `runtime/reference-activities-completion-20261014/native-unified-candidate-20261015`. The Pair component keeps its 26 original/adapted ABCs. The Pair component build's private shared-library copy is evidence only and is excluded from the current 36 packaged assets.

`WorkshopNativeWardrobeBridge.init()` remains the existing injected entry and registers callbacks only. The common owner binds the real `DisplayLoader.Context`, starts one shared Loader, and queues all six modules behind it. The bootstraps receive `sharedOwnerReady:true`, the same context/domain, role and generation; none imports a shared library. ApplicationDomain wrapper object identity is not used: actual class identities and the real LoaderContext slot are checked. All subsequent imports explicitly use the actual context's domain. Unknown pre-existing shared declarations, including a full unproven legacy load, require a fresh game session; only this owner's successful load can be reused. Error/timeout is terminal; imported classes are kept and never retried in another domain.

Public entry ABI:

- `workshopOpenPair(characterId:Number,generation:String):Boolean`, `workshopStatusPair():Object`, `workshopClosePair():void` are added.

- `workshopOpenMoonlight(characterId:Number,generation:String):Boolean`, `workshopStatusMoonlight():Object`, `workshopCloseMoonlight():void` are added by the 36-asset variant.
- Status reads current `Self.ID` even before an open; missing identity stays zero. Open requires the current real role in `main` and synchronously binds expected ID/generation before module/host callbacks.
- The page attaches the matching Pair, Mines, DDPlay, Gypsy or Moonlight host before open, keeps the same generation for this game instance, and owns action UUIDs. Each module has independent callbacks while all character activities share one pending ledger and flight. Closing cancels the requested window only, preserving generation and an in-flight request. A late response stays cached unless the user explicitly reopens. Explicit reopen during a pending GET reuses that GET; a pending POST stays locked and cannot trigger a late open.
- Bootstrap callback names retain each module's `AcceptSnapshot`, `RejectRequest`, `OpenNative`, `CloseNative` and `StatusNative` forms; none conflicts with the eighteen common-owner callbacks.
